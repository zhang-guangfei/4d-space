# Codex 版实机验收

2026 年 11 月 21 日，共享云工作站。Chromium 156.0.8078.79、Python Playwright 1.62.0、WebGL 2 与 ANGLE Vulkan SwiftShader。机器分配四核 CPU 配额，没有物理 GPU 设备。下列帧率是这台机器每秒实际绘制的画面数；硬件加速浏览器需要在对应机器重新采样。

## 复现

在仓库根目录安装 Python 的 Playwright 包，使用系统 Chromium，或用 Playwright 安装其 Chromium。测试器会从临时环回端口的 `/4d-space/codex/` 提供游戏，对前缀以外的请求返回 404。运行产物含原始 JSON 和全视口 JPG。

```sh
python -m pip install playwright
python -m playwright install chromium
python scripts/codex-e2e.py --swiftshader
```

指定系统浏览器可加 `--chromium /path/to/chromium`，可以 `--chapter 1` 或 `--chapter 2` 独立执行。第一章独占剖析使用 `python scripts/codex-e2e.py --profile-corridor --swiftshader`，在同一浏览器上下文依次测量冷启动、静止、持续前进并记录跨门轨迹。测试其他机器的默认渲染后端时，省略 `--swiftshader`。测试现有部署时传 `--url https://zhang-guangfei.github.io/4d-space/codex/`。脚本保留浏览器控制台错误、页面异常、HTTP 错误和失败请求，并在其中任一项出现时以失败状态退出。

“就绪”从 navigation start 计到 Playwright 能观察到开始按钮可用。“点击至画面”在页面收到实际点击事件后计时，等菜单隐藏并经过下一次绘制机会。实际 FPS 取 Babylon 场景连续渲染回调数除以同一段墙钟时间；表中的 P95 为帧间隔的 95 百分位。视频采集、截图和布局切换均在稳态帧采样窗口以外。屏幕输出与 WebGL 内部绘制尺寸分别记录。

第二章直达启动记录了 24 个资源，全部在 `/4d-space/codex/` 内。没有发起第一章雕像模型或贴图请求。换节计时从驱动实际选择器开始到新标题出现并经过两次动画帧，十次范围为 39–289 ms。浏览器主线程仍可观察到初次编译或资源准备的长任务，第二章启动期已记录的最长一项为 404 ms。原始时序和各分辨率几何结果见[第一章测量](validation/codex-chapter1-webgl.json)与[第二章测量](validation/codex-chapter2-webgl.json)。

## 通关与画面

- 第一章从开始菜单进入 W+，用键盘走到观察窗，转动视角，启用望远镜，再通过设置切换原生分辨率。四种桌面尺寸均验证左侧任务、顶栏和右侧六门罗盘的矩形位置。另一路手动输入走入 X+，经两个观察窗分别拍下维纳斯和大卫的正面。能看见眼眶、发绺、衣褶的明暗与门框的金属表面。
- 第二章的全程通关用 WASD 实际移动，走到目标半径内按 F。顺序经过接听暗号、越过隔层密封墙、把天桥两端接合、两种四维本体的连续截面、货栈、反手钥匙、牵环、航服检修和回执。测试先撞上 W1 的封墙与断桥缺口，再绕行或转桥通过；记录接听器距离确实随脚步缩短。另在起始点连续按 E、Q，再试方括号，核对 W 读数、可见几何、摄像机 XYZ 和朝向；等待横向扫描过渡结束后数据仍一致。货栈通过面板按键完成跨层推箱，验证换基、撤销和重置。整个流程读取实际摄像机作导航，没有直接赋值位置或调用规则函数推进小节。
- 开着第一人称视野按 T 释放指针，用鼠标操纵右台，再按 T 捕获。借助浏览器的 `pointerLockElement` 验证每次转换。第一小节按 N 通往下一节，第二小节释放指针后实际点击「下一小节」。最后的回执播放后，通过界面重访全部十个小节。从货栈关键动作处暂停、重载页面，再次进入后核对货运车、观察基底、任务、站位与撤销历史。两个章节使用各自私有的浏览器上下文。
- 第二章在 1280×720、1280×800、1440×900 和 1920×1080 下逐节测量可见文字行、按钮、显示边界和主副画布分隔，各查行动中与显示「下一小节」后的状态，共 80 种组合。额外通过截图观察右台收展、岑遥的头盔和背包、折桥接点、球体截面的轮廓以及货栈上层通路。文字交叉判断是浏览器行框检验，并不代表完成了低视力用户测试。
